## Why

The `conventional-commits` audit rule flags git revert commits as violations. Revert commit messages auto-generated by git (e.g., `Revert "feat: add X"`) do not match the Conventional Commits pattern, producing false positives in audit reports. Merge commits are already excluded via `git log --no-merges`, but revert commits pass through unfiltered. This noise was observed in practice by the Mira reviewer bot on a downstream project using `repository-hygiene`.

## What Changes

- `commit_check.py`: exclude commits auto-generated by `git revert` from validation
- Spec `conventional-commit-audit`: add requirement that revert commits are excluded from validation
- Tests: verify revert commits are not flagged as violations

## Capabilities

### New Capabilities

_None._

### Modified Capabilities

- `conventional-commit-audit`: add requirement that revert commits SHALL NOT be validated, preventing false positives from `git revert` auto-generated messages
